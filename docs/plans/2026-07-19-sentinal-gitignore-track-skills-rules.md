## Summary

**Goal:** Update the generated `.sentinal/.gitignore` so it keeps `project-memory.json` un-ignored AND allows all files under `.sentinal/skills/` and `.sentinal/rules/` (including `*.md` and `*.sh`) to be tracked; safely upgrade existing Sentinal-generated `.gitignore` files without clobbering user customizations.

**Architecture:** Single-file change to the generator constant + `ensureGitignore()` logic in `src/memory/shared.ts`, plus updated tests. No new modules.

**Tech Stack:** TypeScript, `bun test`, git ignore semantics.

## Scope

### In Scope

- Expand `GITIGNORE_CONTENT` (`src/memory/shared.ts:261`) to un-ignore `skills/` and `rules/` (dir + `**`), keeping `project-memory.json`.
- Change `ensureGitignore()` to **upgrade** an existing file **only when its content byte-matches a known prior Sentinal-generated version** (safe migration); otherwise leave it untouched (preserve user customizations).
- Update `src/memory/shared.test.ts` for the new content + upgrade behavior.

### Out of Scope

- `continue-here.md` — stays ignored (user chose "skills + rules only").
- The repo's OWN hand-maintained `.sentinal/.gitignore` (already correct; not generated by this code).
- Any installer/CLI change — `src/memory/shared.ts` is the ONLY generation site (verified: no other `!project-memory.json`/`ensureGitignore` writer in src/cli, src/hooks, targets).

## Context for Implementer

- **Single generation site:** `src/memory/shared.ts` — `GITIGNORE_CONTENT` constant (`:261-265`) written by `ensureGitignore()` (`:267-271`), called from `writeSharedMemory()` (`:82`). No other code writes `.sentinal/.gitignore`.
- **Current content (the "v1" known prior version):**
  ```
  # Ignore everything in .sentinal/ except shared project memory
  *
  !.gitignore
  !project-memory.json
  ```
- **git ignore nested-un-ignore gotcha (critical):** when the parent is ignored by `*`, git will NOT descend into a subdirectory to un-ignore files inside it unless the DIRECTORY itself is first re-included. The working incantation (proven by this repo's own `.sentinal/.gitignore`, which correctly tracks nested `SKILL.md` AND `.sh` files) is: `!skills`, `!skills/`, `!skills/**` (and the same triplet for `rules`). `!skills/**` alone is NOT sufficient.
- **Pattern provenance (precise):** the `!skills`/`!skills/`/`!skills/**` triplet is proven by this repo's `.sentinal/.gitignore` (`git check-ignore` confirms nested `SKILL.md` + a probe `.sh` are TRACKED). ⚠️ BUT the repo's file also contains `!continue-here.md`, which we intentionally OMIT (scope). So the EXACT string this generator emits is NOT identical to the repo file and has not itself been `git check-ignore`-validated — the behavioral test in Task 1 is the authoritative proof that our specific content works. Do not treat the "mirror" as validation; treat the test as validation.
- **Byte-exact upgrade match (caveat):** the source uses LF line endings + a single trailing newline (verified). `KNOWN_PRIOR_GITIGNORES` must store the v1 string byte-for-byte including that trailing `\n`, or the upgrade match silently fails. Reconstruct it from the literal, don't paraphrase.
- **`ensureGitignore` currently early-returns if the file exists** (`:269`) — that's why existing projects never upgrade. The migration must compare existing content against the known prior version(s) and only rewrite on an exact match.
- **Test file:** `src/memory/shared.test.ts` — the `.sentinal/.gitignore` describe block (`:179-216`) asserts current content + the no-overwrite behavior (`:201`). That no-overwrite test must be REPLACED by the new upgrade-or-preserve semantics.

## Testing Strategy

- **Unit (`bun test src/memory/shared.test.ts`):**
  - New content assertions: generated `.gitignore` contains `!project-memory.json`, `!skills/`, `!skills/**`, `!rules/`, `!rules/**`.
  - Behavioral (the real proof): in a temp project, write the generated `.gitignore`, create `skills/x/SKILL.md`, `skills/x/run.sh`, `rules/y.md`, and `project-memory.json`; assert (via `git check-ignore` in the temp git repo) that all are TRACKED (not ignored), and that an arbitrary other file (`.sentinal/scratch.log`) IS ignored.
  - Upgrade: pre-write the exact v1 content → `writeSharedMemory` → assert file now equals the new content.
  - Preserve: pre-write a user-customized `.gitignore` (not matching v1) → assert it is left byte-unchanged.

## Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
| ---- | ---------- | ------ | ---------- |
| Wrong gitignore incantation → files still ignored | Med | High | Mirror the repo's proven `.sentinal/.gitignore`; add a behavioral `git check-ignore` test (not just string match) |
| Upgrade clobbers a user-customized file | Low | High | Only rewrite on EXACT byte-match to a known prior version; else leave untouched |
| Future content revision leaves a new "prior" version un-upgradable | Low | Low | Keep an array of known prior versions (`KNOWN_PRIOR_GITIGNORES`) for the match set; append when content changes |

## Pre-Mortem

1. **Files still ignored after fix** (Task 1) → Trigger: the behavioral `git check-ignore` test shows `skills/x/run.sh` ignored. Cause: used `!skills/**` without `!skills/`. Fix: include the dir-level un-ignore lines.
2. **Existing project silently not upgraded** (Task 1) → Trigger: upgrade test fails — v1 content not rewritten. Cause: byte mismatch (trailing newline). Fix: match against the exact stored v1 string incl. trailing newline.
3. **User customization clobbered** (Task 1) → Trigger: preserve test fails. Cause: upgrade check too loose (e.g. substring match). Fix: exact full-content equality only.
